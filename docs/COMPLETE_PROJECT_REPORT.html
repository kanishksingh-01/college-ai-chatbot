INTRODUCTION :
The AI Chatbot for College is a web-based application, deployed live and publicly accessible, designed to provide instant, 24x7 answers to common student queries such as admission details, fee structure, exam timetable, attendance rules, library timings, course information, faculty contact details, branch/course change procedures, placements, hostel accommodation, scholarships, and campus facilities. The system uses rule-based keyword detection with typo-tolerant fuzzy matching to understand student questions and respond with accurate information stored in a database.
Every academic year, college administrative staff spend a significant amount of time answering the same repetitive questions from students. The AI Chatbot for College solves this problem by providing a centralized, always-available platform where students can get immediate answers without visiting the college office or waiting for staff availability. The chatbot is also configured as an installable Progressive Web App with voice input and output capabilities, so students can add it to their phone's home screen and interact using text or voice.
PROBLEM STATEMENT :
Students often struggle to get quick answers to basic college-related questions, especially outside office hours. College administrative staff are repeatedly asked the same set of questions regarding admission, fees, timetables, and attendance, which adds to their daily workload and reduces their availability for other important tasks.
There is currently no centralized, automated system in most colleges that allows students to self-serve this information at any time. This results in delays, unnecessary visits to the college office, and inefficient use of staff time.

PROPOSED SYSTEM :
The proposed system, AI Chatbot for College, is a web-based chatbot application that instantly answers common student queries using rule-based keyword matching with fuzzy, typo-tolerant fallback. It integrates a student login feature, a securely authenticated admin panel with live analytics, voice interaction, and a chat history log into a single platform, and is deployed live with a continuous deployment pipeline (GitHub to Render), so updates go live automatically.
The system allows students to type their queries in plain text, speak via microphone, or tap quick-reply category buttons, which the chatbot analyzes for relevant keywords before fetching the correct predefined answer from the database. Students who log in with their registration number receive personalized responses, such as their own attendance percentage, fee dues, CGPA score, assigned faculty mentor, or exam date, in addition to general FAQ answers. Answers containing tabular data (such as the fee structure or exam timetable) are rendered as properly formatted tables in the chat interface rather than plain text.
PROJECT DESCRIPTION :
AI Chatbot for College is a web-based chatbot application designed to reduce the workload of college administrative staff while giving students round-the-clock access to important information.
The system provides a polished chat interface built with HTML, modern CSS with Dark/Light theme switching, and JavaScript, connected to a Python Flask backend. When a student types or speaks a query, the backend matches keywords against an expanded set of 14 categories — admission, fees, timetable, attendance, library, courses, faculty, branch change, placements, hostel, scholarships, clubs, emergency helplines, and campus map — and returns the corresponding answer from the SQLite database. An admin panel allows the college staff to update this information whenever it changes and export audit logs as CSV.

9. Explain the data flow of your application.
When a student types a message, speaks via voice input, or taps a quick-reply button, the browser sends it to the Flask backend via the /chat endpoint as JSON. The backend first checks whether the student is logged in and asking about their own data (e.g. “my attendance”, “my cgpa”); if so, it queries the students table directly. Otherwise, it runs the message through the match_query() function, which checks it against the keywords column of every row in the college_info table, using exact matching first and fuzzy matching as a fallback. The best matching answer is retrieved, the query-response pair along with row ID is saved into the chat_history table, and the response is sent back to the browser as JSON, where JavaScript renders it in the chat window (including converting any table-formatted answers into an actual HTML table and triggering audio chimes).

1. What is UML?
UML (Unified Modeling Language) is a standardized, general-purpose visual modeling language used in software engineering to specify, visualize, construct, and document the structure and behavior of a software system. It provides a common set of diagram types and notations so that developers, designers, and stakeholders can understand a system's design regardless of the programming language used to build it.
2. What is the use of UML?
UML is used to model a software system before and during development. It helps a team plan the system's structure (what data/entities exist and how they relate), its behavior (how users interact with it and how processes flow), and its architecture, before writing code. It improves communication between team members, makes the design easier to review and modify, and serves as documentation for future maintenance. For the AI Chatbot for College project, UML diagrams were used to plan how students and the admin interact with the system, and how the database entities relate to each other.
3. Explain types of UML diagram with example.
UML diagrams are broadly divided into two categories: Structural diagrams (show the static structure of a system) and Behavioral diagrams (show the dynamic behavior).
  • Class Diagram (Structural) – Shows classes, their attributes, methods, and relationships. Example: in this project, a Student class with attributes roll_no, name, attendance, fees_due, course, semester, cgpa, and mentor.
  • Use Case Diagram (Behavioral) – Shows actors and the actions (use cases) they can perform with the system. Example: a Student actor performing “Ask FAQ”, “Voice Input”, and “Login” use cases.
  • Sequence Diagram (Behavioral) – Shows the order of messages exchanged between objects over time. Example: Student sends query → Flask backend queries SQLite → response back to Student.
  • Activity Diagram (Behavioral) – Shows the flow of control/steps in a process, similar to a flowchart. Example: decision logic determining whether to fetch personal records or match general FAQs.
  • Component Diagram (Structural) – Shows how software modules are organized. Example: Frontend UI component, Flask backend component, and SQLite database component.
  • Deployment Diagram (Structural) – Shows the physical/hardware setup a system runs on. Example: Client browser → Render cloud Linux container → SQLite storage.

ASSIGNMENT 3

1. What is Project Life Cycle and its Main Characteristics?
A Project Life Cycle is the series of phases a software project passes through from initiation to completion — typically Requirement Analysis, Design, Implementation (Coding), Testing, Deployment, and Maintenance. It provides a structured path for planning, executing, and delivering a project in a predictable, manageable way.
Main characteristics:
  • • Defined start and end points, with clear phases in between.
  • • Each phase produces specific deliverables (e.g. requirement document, design diagrams, working code, test reports).
  • • Progress can be tracked and measured against each phase.
  • • Resources (time, people, tools) are planned and allocated per phase.
  • • Risks are identified and managed throughout the cycle, not just at the end.
2. Explain following SDLC models.
i) Waterfall Model
A linear, sequential model where each phase (Requirements → Design → Implementation → Testing → Deployment → Maintenance) must be completed before the next begins. It is simple to understand and manage, but inflexible — changes are difficult once a phase is finished. Best suited for projects with clear, fixed requirements.
ii) Iterative Model (Used in This Project)
The system is developed through repeated cycles (iterations), with each iteration adding or refining functionality. A basic working version is built first, then improved in successive iterations based on feedback. This project strictly followed an iterative approach — starting with a basic chatbot (Iteration 1), adding database persistence (Iteration 2), student login (Iteration 3), admin panel with password hashing (Iteration 4), fuzzy matching & PWA support (Iteration 5), and finally voice input/output, dark mode, expanded student profile records (CGPA/mentor), and CSV analytics export (Iteration 6).
iii) Spiral Model
Combines iterative development with a strong focus on risk analysis. Each cycle (spiral) passes through four phases: planning, risk analysis, engineering, and evaluation. It is well suited for large, complex, high-risk projects where requirements may evolve.
iv) V-shaped Model
An extension of the Waterfall model where each development phase has a corresponding testing phase, forming a V shape. For example, requirement analysis pairs with acceptance testing, and system design pairs with system testing. It emphasizes verification and validation at every stage, but like Waterfall, is less flexible to changing requirements.
v) Agile Model
An iterative and incremental model that delivers working software in small, frequent cycles called sprints, with continuous feedback and collaboration between the team and stakeholders. It embraces changing requirements even late in development and prioritizes working software over extensive documentation.

1. Define Software Testing.
Software Testing is the process of evaluating a software application to verify that it behaves as expected, meets its requirements, and is free of defects. It involves executing the program with test inputs and comparing actual results with expected results. For this project, testing included automated unit testing (using Python's unittest) and manual functional testing to check that all 14 FAQ categories returned correct answers, that typo-tolerant matching worked, and that login/authentication behaved correctly for valid and invalid inputs.
2. What is Risk Identification?
Risk Identification is the process of recognizing potential problems that could negatively affect a project before they occur, so they can be planned for or mitigated. Examples relevant to this project include: the free hosting tier going to sleep and delaying responses (~30s cold start), the admin database not being updated regularly leading to outdated answers, or keyword-based matching failing to understand oddly phrased questions (mitigated using difflib fuzzy matching).
3. What is SCM?
SCM (Software Configuration Management) is the discipline of tracking and controlling changes to a software project's files over time, ensuring consistency and enabling collaboration. In this project, SCM was implemented using Git for version control and GitHub for hosting the repository, allowing every change to be tracked, committed with a message, and safely pushed to the live deployment on Render with automated continuous integration.
4. Define Debugging.
Debugging is the process of identifying, analyzing, and fixing errors (bugs) in a program's source code. It involves reproducing the faulty behavior, tracing it back to its root cause (often using logs, error messages, or print statements), and correcting the code so the program behaves as intended.
5. Explain Configuration Audit.
A Configuration Audit is a formal review conducted to verify that a software product conforms to its specified requirements and that all configuration items (code, documentation, versions) are consistent and correctly recorded. It typically has two parts: a Functional Configuration Audit (verifying the software meets its functional and performance requirements) and a Physical Configuration Audit (verifying the software matches its technical documentation).
6. Differentiate Between Black Box Testing And White Box Testing.
Black Box TestingWhite Box Testing
Tests functionality without knowledge of internal code structure. Tests internal code structure, logic, and paths directly.
Performed from the end-user's perspective (inputs and outputs). Performed from a developer's perspective (code-level logic).
Example: checking the chatbot returns the right FAQ answer for a given query. Example: checking the match_query() function's keyword-matching scoring logic directly.
Does not require programming knowledge. Requires programming knowledge to design test cases.

7. What Do You Mean By Metrics?
Software Metrics are quantitative measures used to assess various aspects of a software project, such as its size, complexity, quality, or the productivity of the development process. Examples include lines of code, number of defects found, response time, or number of test cases passed (e.g. 7/7 automated unit tests passed in this project). In this application, live KPI metrics are also displayed on the admin dashboard showing Total Active FAQs, Total Queries Handled, and Registered Students.
8. What Do You Mean By Version Control?
Version Control is a system that records changes to files over time so that specific versions can be recalled, compared, or reverted later, and multiple people can collaborate without overwriting each other's work. This project uses Git for version control, with GitHub used to commit and push changes, and Render automatically redeploying the latest committed version.
9. Explain Object Oriented Software Engineering.
Object Oriented Software Engineering (OOSE) is an approach to designing and building software around “objects” — units that bundle data (attributes) and behavior (methods) together, based on real-world entities. It relies on concepts such as encapsulation, inheritance, and polymorphism. In this project, the database design reflects an object-oriented way of thinking about entities — Student, CollegeInfo, ChatHistory, and Admin — each with clearly defined attributes and methods.
10. Explain Various Types of Testing in details.
Unit Testing – Testing individual functions or components in isolation. Example: testing the match_query() function alone with sample inputs and fuzzy typos.
Integration Testing – Testing how multiple components work together. Example: testing that the Flask route correctly calls the database, logs chat history, and returns a JSON response.
System Testing – Testing the complete, integrated application as a whole. Example: using the live deployed chatbot end-to-end, from speaking a question to receiving an answer.
Acceptance Testing – Testing to confirm the system meets user requirements. Example: confirming a student can log in and see their correct attendance, CGPA, and mentor details.
Regression Testing – Re-testing existing features after a change, to confirm nothing that previously worked has broken. Example: re-testing FAQ answers and table rendering after adding dark mode and voice features.
Performance Testing – Testing how the system behaves under load or response-time constraints. Example: measuring API latency and documenting the free-tier hosting's cold-start delay after inactivity.
