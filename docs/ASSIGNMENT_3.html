1. What is Project Life Cycle and its Main Characteristics?
A Project Life Cycle is the series of phases a software project passes through from initiation to completion — typically Requirement Analysis, Design, Implementation (Coding), Testing, Deployment, and Maintenance. It provides a structured path for planning, executing, and delivering a project in a predictable, manageable way.
Main characteristics:
  • • Defined start and end points, with clear phases in between.
  • • Each phase produces specific deliverables (e.g. requirement document, design diagrams, working code, test reports).
  • • Progress can be tracked and measured against each phase.
  • • Resources (time, people, tools) are planned and allocated per phase.
  • • Risks are identified and managed throughout the cycle, not just at the end.
2. Explain following SDLC models.
i) Waterfall Model
A linear, sequential model where each phase (Requirements → Design → Implementation → Testing → Deployment → Maintenance) must be completed before the next begins. It is simple to understand and manage, but inflexible — changes are difficult once a phase is finished. Best suited for projects with clear, fixed requirements.
ii) Iterative Model (Used in This Project)
The system is developed through repeated cycles (iterations), with each iteration adding or refining functionality. A basic working version is built first, then improved in successive iterations based on feedback. This project strictly followed an iterative approach — starting with a basic chatbot (Iteration 1), adding database persistence (Iteration 2), student login (Iteration 3), admin panel with password hashing (Iteration 4), fuzzy matching & PWA support (Iteration 5), and finally voice input/output, dark mode, expanded student profile records (CGPA/mentor), and CSV analytics export (Iteration 6).
iii) Spiral Model
Combines iterative development with a strong focus on risk analysis. Each cycle (spiral) passes through four phases: planning, risk analysis, engineering, and evaluation. It is well suited for large, complex, high-risk projects where requirements may evolve.
iv) V-shaped Model
An extension of the Waterfall model where each development phase has a corresponding testing phase, forming a V shape. For example, requirement analysis pairs with acceptance testing, and system design pairs with system testing. It emphasizes verification and validation at every stage, but like Waterfall, is less flexible to changing requirements.
v) Agile Model
An iterative and incremental model that delivers working software in small, frequent cycles called sprints, with continuous feedback and collaboration between the team and stakeholders. It embraces changing requirements even late in development and prioritizes working software over extensive documentation.
