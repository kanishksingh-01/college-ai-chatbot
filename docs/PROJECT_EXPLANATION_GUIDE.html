AI Chatbot for College — Everything Explained in the Easiest Way
⚡ WHAT IS THIS PROJECT IN 30 SECONDS?

Imagine having a super-smart college receptionist who never sleeps, never gets tired, speaks and listens in English, remembers every student's attendance and fee status, and answers college questions instantly. That is exactly what this project is! It is a full-stack, voice-enabled AI Campus Chatbot and Student Portal built specifically for GH Raisoni College using Python (Flask), SQLite, and modern Web Speech / PWA technologies.

1. THE REAL-WORLD PROBLEM WE SOLVED
❌ The Traditional College Way ✅ Our AI Chatbot Solution
Students wait in long physical queues at the admin/accounts desk for minor inquiries (fee dues, exam dates). Instant 24/7 web access from mobile or laptop with zero waiting time.
Staff repeatedly answers the exact same 50 questions daily, wasting hours of manual productivity. Automated NLP Knowledge Base answers admissions, syllabus, timings, and campus queries in milliseconds.
Students have no quick private way to check their personal attendance percentage or fee balances. Secure student login with Registration No. (e.g., ISTU...) delivers personalized real-time stats.
Static noticeboards and clunky PDF circulars are easily missed by students on the go. Interactive search with quick suggestion pills and spoken audio responses (voice read-aloud).
2. THE THREE CORE PILLARS OF THE SYSTEM
🤖
1. Public AI Assistant
Open to any visitor, parent, or applicant. Answers admissions, eligibility, fees, placement stats, and campus facilities with smart typo tolerance.
👤
2. Student Portal
Authenticated zone. When a student enters their Roll No, the bot greets them personally and answers "What is my attendance?", "Do I have fee dues?", etc.
🛡️
3. Admin Control Panel
Protected back-office. College administrators can add/edit FAQs, monitor live chat logs, track feedback, and export logs to CSV with one click.

System Mechanics & Engineering

HOW IT WORKS UNDER THE HOOD

Step-by-Step Lifecycle of a User Message (From Voice/Typing to Response)
THE LIFECYCLE OF A QUESTION: 7 SIMPLE STEPS
STEP 1
Student Inputs Query (Typing or Speaking): The user types in the input box or taps the microphone icon. The browser's native Web Speech API converts speech into text instantly.
STEP 2
Async HTTP Request (AJAX / Fetch): JavaScript captures the text, triggers a smooth local audio cue, shows a bouncing "Bot is typing..." indicator, and dispatches a JSON POST request to /chat.
STEP 3
Session & Student Context Check: Flask inspects the active browser session. If a student is logged in (e.g. ISTU25010120001), the server first checks if the query asks for personalized data (attendance, marks, fees).
STEP 4
Intelligent Fuzzy NLP Engine: If it's a general question, the bot runs the query through our custom NLP matcher in app.py. It cleans tokens and uses Python's difflib.get_close_matches to forgive typos (e.g., "admisn", "timtable").
STEP 5
Database Lookup & Scoring: The engine scores matching knowledge-base rows from college_info. The answer with the highest multi-word keyword confidence is selected. If confidence is too low, it triggers a helpful fallback with quick buttons.
STEP 6
Chat History Logging: The bot inserts the query, response, student ID, and timestamp into the chat_history table in SQLite and returns the response JSON along with a unique history_id.
STEP 7
Rendering & Voice Synthesis: JavaScript receives the response, renders bold text, links, and markdown lists, plays a chime, speaks the response aloud using SpeechSynthesis, and displays Thumbs Up/Down rating buttons!
💡 WHY IS THIS BETTER THAN A GENERIC LLM (like raw ChatGPT)?

1. Zero Hallucinations: The chatbot only gives verified, accurate college data stored in the database.
2. Zero API Cost & Infinite Speed: It runs completely on local Python/SQLite without needing paid OpenAI tokens.
3. Data Privacy: Student records and internal grades never leave the college server.

Technology Stack & Feature Highlights

TECH STACK & SPECIAL FEATURES

Tools Used and the 7 Standout Features that Impress Examiners
1. OUR COMPLETE TECHNOLOGY STACK
Component Technology Why We Chose It
Frontend UI HTML5, CSS3, Modern JavaScript (ES6+) Blazing fast loading, 100% responsive on mobiles & desktops, zero heavy npm bloat.
Voice I/O Native Web Speech API (STT & TTS) Speech recognition and natural voice playback directly inside Chrome/Edge without extra libraries.
Sound Synthesis Web Audio API (OscillatorNode) Generates pleasant chime frequencies directly via code without loading heavy MP3 audio files.
Backend Engine Python 3.11 + Flask Microframework Lightweight, robust routing, simple session management, and built-in SQLite integration.
Database SQLite 3 (Embedded Relational DB) Zero setup, ACID compliant, serverless single-file storage (college_chatbot.db).
Cloud Deployment Render PaaS (Cloud Linux Container) Automatic HTTPS/TLS 1.3 encryption, CI/CD GitHub integration, 24/7 global availability.
2. THE 7 SPECIAL FEATURES EXPLAINED SIMPLY
1. 🎙️ Two-Way Voice Interaction: Tap the mic to talk to the bot; click the speaker icon on any message to hear it read aloud with smooth speech synthesis.
2. 👤 Personalized Student Intelligence: When logged in, asking "what is my attendance?" returns your actual percentage (e.g. 88.5%) and warns you if below 75%!
3. 🧠 Typo-Tolerant NLP Engine: Students make mistakes when typing quickly. Typing "admisn eligibility" or "feees structre" still matches the right answer perfectly!
4. 👍👎 Quality Feedback Loop: Every answer has Like/Dislike buttons. Clicking a button immediately updates the database row, allowing admins to track bot satisfaction.
5. 📱 Progressive Web App (PWA): Students can click "Add to Home Screen" on Android/iOS/Windows to install the bot like an official native app with an app icon.
6. 📊 Admin Dashboard & CSV Export: Administrators have a password-protected portal to add new FAQs on the fly and download the entire chat history as an Excel/CSV file.
7. 🔒 Bulletproof Security: Passwords are never stored in plain text. We use PBKDF2 with SHA-256 hashing (600,000 rounds) and parameterized SQL queries to prevent SQL Injection.

Viva Voce & Project Defense Mastery

TOP VIVA QUESTIONS & BULLETPROOF ANSWERS

Exactly What to Say When Your Teacher or External Examiner Asks You
Q1: "Is this chatbot using ChatGPT or an external API?"
Answer: "No, sir/ma'am. We intentionally engineered an in-house rule-based Natural Language Processing engine using Python's difflib and keyword scoring. This guarantees 100% data privacy for student records, zero latency, zero cloud API costs, and prevents AI hallucinations."
Q2: "What happens if a student types a spelling mistake like 'admisn'?"
Answer: "Our NLP engine has fuzzy matching enabled with an 80% similarity threshold. When a word like 'admisn' is typed, difflib.get_close_matches automatically detects that it is 85% similar to 'admission', awards a match score, and returns the correct admission guidelines."
Q3: "How does the bot know a student's personal attendance?"
Answer: "When a student logs in using their Registration Number, Flask saves their roll number in a secure server session. When the bot detects personal intent words like 'my attendance' or 'my fees', it intercepts the message and performs an SQL query on the students table for that specific roll number."
Q4: "How is the system secured against hackers or data leaks?"
Answer: "We implemented 3 major security defenses: First, admin passwords are protected using industry-standard PBKDF2 SHA-256 password hashing. Second, all SQL queries use parameterized placeholders (?) to prevent SQL Injection attacks. Third, the live application is served over HTTPS with TLS 1.3 encryption on Render Cloud."
Q5: "How does the voice feature work?"
Answer: "We use the browser's native Web Speech API. For Speech-to-Text, webkitSpeechRecognition captures the student's voice and converts speech to text. For Text-to-Speech, window.speechSynthesis converts the bot's text answer into clear audio output."
Q6: "What is your sequence diagram termination condition?"
Answer: "Our sequence diagram doesn't just hang open; it features an explicit End Chat flow. When the user completes their session or sends a termination command ('bye'), the backend returns a session summary and both the browser and server lifelines are formally destroyed with the UML ✕ destruction mark."
